# Экраны: что показываем и чего нельзя забыть

Три экрана и одна панель. Всё остальное — потом.

---

## 1. Учитель → План (`GET /api/classes/1/plan`)

Список уроков по датам: дата, тема, коды целей, статус, есть ли готовый пакет.

- Ближайший урок выделен — с него начинается демо.
- Кнопка **«Собрать пакет»** → `POST /api/lessons/{id}/pack`.
  Ответ идёт **до 30 секунд**: покажи текст «Агент собирает урок: КСП, задания, разбор ошибок»,
  а не голый спиннер. После ответа — сразу переход на экран урока.
- Коды целей показывай как есть (`7.2.1.4`) — это фишка продукта, жюри должно их видеть.

## 2. Учитель → Урок (`GET /api/lessons/{id}` + пакет)

Блоки сверху вниз:

1. **КСП** — этапы с минутами (`ksp.stages`), результаты обучения (`outcomes`), дифференциация.
2. **Объяснение темы** (`explanation`) — просто текст.
3. **Типовые ошибки** (`common_mistakes`) — три колонки: ошибка / почему / как исправить.
4. **Задания в классе** (`classwork`) — с пометкой уровня 1–3.
5. Кнопка **«Выдать домашку классу»** → `POST /api/lessons/{id}/homework`.
   В ответ приходит список учеников и их фокусные цели — покажи таблицей
   «ученик → сколько заданий → над чем работает». Это кадр демо №3: видно, что у всех разное.

## 3. Ученик → Моя домашка (`GET /api/students/{id}/homework?lesson_id=`)

Список заданий, у каждого поле ответа. Кнопка «Сдать» → `POST /api/submissions`.

**Телеметрия — обязательна.** По каждому полю собираем и отправляем в `answers[].telemetry`:

```js
{ seconds: 92,   // от первого фокуса до отправки
  pastes: 0,     // число событий paste
  edits: 7 }     // сколько раз менялось значение
```

Ловим так: `onFocus` — засечь время; `onPaste` — счётчик; `onChange` — счётчик правок.
Это половина сигналов детектора, без них фича на демо не сработает.

После отправки на том же экране — **разбор**: баллы по каждому заданию, какие дескрипторы
засчитаны, текст фидбека, и изменение освоенности («7.2.1.4: было 0.20 → стало 0.55»).

Ещё кнопка **«Сфотографировать работу»**:
`<input type="file" accept="image/*" capture="environment">` → сжать до ~1600px по длинной
стороне → `POST /api/submissions/photo` (multipart). Ответ того же формата, плюс блок `ocr`.
Если `ocr.qr_found === false` — покажи честную плашку «распознано неточно, учитель проверит».

## 4. Учитель → Карта класса (`GET /api/classes/1/mastery`)

Таблица целей: код, формулировка, процент освоения, сколько учеников провалило, рекомендация.

- Провал (`avg < 0.5`) — красным. Это кадр демо №5: после проверки строка должна **покраснеть
  на глазах**, поэтому не кешируй ответ и обнови данные после сдачи.
- Ниже — список учеников с их пробелами.

## 5. Панель «Проверьте» (`GET /api/teacher/review-queue?class_id=1`)

Карточка на каждую спорную работу:

```
Айдар · задание 501 · предложено 1 из 2 балла · уверенность 0.44
Индекс внешней помощи: 0.81 (высокий)
  • метод «подобие треугольников» относится к цели 8.1.2.3 (2 четверть 8 класса)
  • ответ вставлен из буфера, 4 секунды на задание
  • освоенность цели у ученика 0.20, работа без помарок
[ Принять ]  [ Исправить балл ]
```

Кнопки → `POST /api/results/{id}/confirm`.

**Формулировки важны.** Нигде не пишем «списал» или «использовал ИИ» — только «индекс внешней
помощи» и основания. Никаких автоматических санкций: решение принимает учитель. Это то, о чём
нас обязательно спросят на защите.

## Финальный кадр демо

Экран, где рядом два ученика: **Айдар** (сдал с телефона) и **Дана** (сдала на бумаге, учитель
сфоткал). Разные каналы — одинаковая персонализация и одинаковая карта освоения. Сделай это
одним простым экраном со сравнением, без изысков: две колонки, сверху канал, снизу задания и
прогресс по целям.

Причина, по которой это вообще есть: две из пяти семей в Казахстане не имеют компьютера, и
продукт спроектирован от бумаги, а не от экрана.

## PWA

manifest, иконка, `display: standalone`, проверить установку с телефона на домашний экран.
Нативного приложения нет принципиально — App Store в наши сроки не влезает.
