# AI Sana Challenge Hub

Веб-платформа по [кейсу AI Sana](https://docs.google.com/document/d/1lFWekP2SirFarATKkWa5neHNL5DlhjZKkUacvGyZk8k/edit): бизнес уточняет задачу и повышает её рейтинг, команда сама выбирает задачу и отправляет предложение, бизнес вручную решает, с кем работать.

**Публичное демо:** https://challenge-hub-production.up.railway.app

## Запуск

Нужны Python 3.11–3.14, Node.js 18+ и npm. На macOS, Linux или в WSL из корня репозитория:

```bash
./run.sh
```

Откройте http://localhost:8000. Скрипт устанавливает зависимости, собирает фронтенд и запускает FastAPI вместе с веб-интерфейсом. **При каждом запуске он пересоздаёт SQLite-базу** с демонстрационными данными. Ключ OpenAI не обязателен: без него основной сценарий работает на локальной заглушке. Проверка сервера: http://localhost:8000/api/health.

## Демонстрация за пять минут

Регистрация для демо не нужна: роль и участник выбираются в шапке.

1. **Бизнес → «Новая задача».** Выберите ТОО «Агро Север» и введите: «Хотим понимать, какие поля скоро потребуют полива». Платформа задаст не менее трёх уточняющих вопросов.
2. **Уточнение → карточка.** Укажите потребность сократить расход воды на 20%, данные датчиков за 2 года в CSV, дашборд с прогнозом на 7 дней и критерий точности не ниже 80%. Дополните карточку пользователями, ограничениями и контактом. Покажите расшифровку баллов и рост рейтинга.
3. **Подтверждение → каталог.** Подтвердите карточку и опубликуйте её. Откройте каталог от роли команды: задача стоит по подтверждённому рейтингу.
4. **Команда → отклик.** Выберите DataCats, откройте задачу и отправьте идею, план, срок и ссылку на прототип.
5. **Бизнес → решение.** В «Мои задачи» откройте «Отклики», сравните предложения и вручную примите или отклоните отклик. Команда увидит решение в «Мои отклики».

Шаг 8 ТЗ: после фактического результата бизнес может подтвердить выполненный этап у принятого отклика. Команда получает 10 баллов; счёт виден в «Панели программы». Полные тексты для ввода и порядок показа — в [сценарии демо](docs/04-demo.md).

## Рейтинг задачи

Рейтинг считает код в `backend/app/rating.py`, а не ИИ. Формула: сумма начисленных баллов по семи показателям минус вычеты за отписки, бессмысленный или повторяющийся текст и набор ключевых слов; минимум — 0, максимум — 100. В интерфейсе показаны причины каждого начисления и сведения, которые помогут улучшить карточку.

| Показатель | Начисление | Максимум |
|---|---|---:|
| Контекст и потребность | Контекст 6 + потребность 6 + число в каждом поле по 4 | 20 |
| Данные и материалы | Описание 8 + источник 6 + формат 3 + объём или период 3 | 20 |
| Ожидаемый результат | Описание 8 + подробность 4 + число 3 | 15 |
| Критерии успеха | Описание 5 + числовая цель 7 + метрика 3 | 15 |
| Ограничения | Описание 5 + числовая граница 3 + вид ограничения 2 | 10 |
| Пользователи | Кто использует результат 6 + уточнение роли 4 | 10 |
| Связь с бизнесом | Контакт 6 + формат взаимодействия 4 | 10 |

Текущие правки дают **предпросмотр** баллов. Официальный рейтинг и место опубликованной задачи меняются после ручного подтверждения карточки. Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Подробные проверки и вычеты — в [формуле рейтинга](docs/03-rating.md).

## Каталог и выбор команды

Все опубликованные задачи видны командам, включая задачи с низким рейтингом; на них тоже можно откликнуться. Каталог сортирует задачи по официальному баллу по убыванию, при равенстве — по времени публикации (новые выше). Фильтры: отрасль задачи (тема в этом MVP) и уровень готовности. Задачи уровня 0–39 помечаются как требующие уточнения, 90–100 выделяются.

Рекомендации показывают совпадения темы задачи с интересами, навыками и технологиями команды, начиная с уровня «рабочая». Они не скрывают остальные задачи и не назначают исполнителя. Команда может отправить сколько угодно откликов; бизнес выбирает одну, несколько или ни одной команды.

## ИИ и архитектура

```text
браузер (React + Vite) → FastAPI (/api и статические файлы) → SQLite
                              │
                              └→ OpenAI через backend/app/llm.py
```

ИИ разбирает черновик, формулирует вопросы и собирает редактируемую карточку. Помощник карточки предлагает текст для слабых полей с прогнозом прироста. Предложения ИИ сверяются с дословными цитатами из текста бизнеса: значение без подтверждающей цитаты отбрасывается. Человек редактирует и подтверждает карточку; рейтинг считает код, а команду вручную выбирает бизнес. Без внешнего API основной сценарий доступен на заглушке, а помощник сообщает о недоступности.

Промпты, схемы входа и выхода, а также обработка некорректного ответа доступны на странице «Как работает ИИ» (`#/ai`) и через `GET /api/ai/spec`. API-контракт — [docs/02-api.md](docs/02-api.md). Синтетический сид содержит по 5 черновиков, карточек, команд и откликов.

## Сценарии проверки

- **Основной:** пройти пять шагов демо выше; рейтинг растёт, задача появляется в каталоге, решение бизнеса видно команде.
- **Подтверждение:** изменить опубликованную карточку; её официальное место в каталоге должно обновиться только после подтверждения.
- **Открытый каталог:** опубликовать задачу с рейтингом ниже 40; она остаётся видимой и принимает отклики.
- **Без ключа ИИ:** запустить без `OPENAI_API_KEY`; черновик, вопросы, карточка, публикация и отклик продолжают работать.

Автоматический сценарий API после `./run.sh`: в другом терминале выполните `cd backend && ../.venv/bin/python -m pytest tests/test_scenario.py`. Дополнительные проверки — в [docs/04-demo.md](docs/04-demo.md).

## Примечания для сдачи

В проекте используются FastAPI, uvicorn, pydantic, OpenAI SDK, python-dotenv, pytest, httpx, React и Vite; SQLite входит в Python. До начала соревновательной части были подготовлены структура репозитория, общий каркас FastAPI и тестовая фикстура. Схема данных, сид, рейтинг, ИИ-сценарий, каталог, отклики и интерфейс сделаны после публикации кейса.

Публичный сервис хранит SQLite в контейнере: новый деплой заново загружает демо-данные. Переключатель ролей предназначен для демонстрации и не проверяет личность пользователя.
