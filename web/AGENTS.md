# web/ — фронт AI Sana Challenge Hub. План для агента

Сначала прочитай (обязательно, в этом порядке):
1. `../AGENTS.md` — что строим, правила хакатона, кто что делает.
2. `../partner/00-START-HERE.md` — экраны и правила для веба.
3. `../partner/01-api.md` — **замороженный контракт API**. Единственный источник правды о полях.

## Границы

- Правишь **только `web/`**. `backend/`, `docs/`, `partner/`, `seed/`, корневые файлы — чужие.
  Нужно поле или роут, которого нет в `01-api.md`, — остановись и напиши, что нужно: человек
  передаст Арслану. Поля на своей стороне не выдумывай.
- **Коммит после каждого шага, push не реже раза в час** (правило хакатона, промежуточный результат).
  В коммит — только файлы из `web/` (`git add web/`, не `git add -A`). Перед push —
  `git pull --rebase`; конфликт вне `web/` не решай сам — остановись и скажи.
- Подписи полей, показатели, уровни, отрасли, примеры черновиков — из `GET /api/meta`, не зашивать.

## Стек

- Vite + React 18, JS (без TypeScript), без UI-библиотек и CSS-фреймворков, свой CSS.
- Роутинг — hash (`#/new`, `#/task/7`, `#/catalog`), без react-router: один файл `router.js`.
- Все запросы — только через `src/api.js`. Dev-прокси `/api` → `http://localhost:8000`.
- Сборка в `web/dist` — её раздаёт FastAPI, поэтому CORS нет и деплой один.
- Палитра: тёмный `#172c3b`, акцент `#e2a55c` / `#aa7039`, фон `#f5f3ed`, светлая зелень
  `#e8eeea`, шрифт Inter / system-ui. Спокойно, без анимаций и градиентов.
- Ширина от 1024px — основная; на 390px не должно разваливаться (ТЗ §7 адаптацию не требует).

## Моки

Бэк может быть не поднят. В `src/api.js` флаг `USE_MOCKS` (`import.meta.env.VITE_USE_MOCKS === 'true'`).
Моки в `src/mocks.js` — **строго по примерам из `01-api.md`**, с состоянием в памяти, чтобы
сценарий проходился целиком: создать задачу → ответить → карточка → подтвердить → опубликовать →
отклик → решение. Рейтинг в моках — упрощённый пересчёт по весам из `meta.indicators`
(поле непустое → полный вес, для пары полей — половина за каждое). Задержка 600 мс на POST,
чтобы лоадеры было видно.

## Шаги

Каждый шаг — одна сессия. Шаг сделан, только когда прошли пункты «Готово, если».
Начало любой сессии: «Прочитай `web/AGENTS.md` и три файла из него. Делай шаг N».

После каждого доработанного экрана дай напарнику короткое описание: маршрут и назначение,
что изменилось, как проверить основные действия на localhost и на публичном сайте, а также
что пока не проверено или зависит от нового деплоя. Отчёт по одному экрану — перед переходом
к следующему, чтобы напарник мог сразу оценить результат.

### W1. Каркас

> Создай Vite + React приложение в `web/` по разделам «Стек», «Моки», «Структура» этого файла.
> `package.json` со скриптами `dev` (`vite --host`), `build`, `preview`; `vite.config.js` с
> прокси `/api` → `http://localhost:8000`. `api.js` — функции на **все** роуты из
> `partner/01-api.md`, ошибки бросает как `Error` с `error.message` из тела и `status`.
> `mocks.js` — полный набор по примерам контракта (минимум 2 бизнеса, 5 команд, 5 примеров
> черновиков, 3 опубликованные задачи разного уровня, 2 отклика). Шапка: логотип «Challenge Hub»,
> переключатель роли (`GET /api/businesses` + `GET /api/teams`, выбор хранится в `localStorage`),
> навигация по роли: бизнес — «Новая задача», «Мои задачи»; команда — «Каталог», «Мои отклики»;
> всем — «Как работает ИИ». Экраны пока заглушки с заголовком.
> Если `/api/health` недоступен и моки выключены — плашка «Бэкенд не отвечает».

Готово, если: `npm i && npm run build` без ошибок; `VITE_USE_MOCKS=true npm run dev` —
переключается роль, меняется меню, переходы по hash работают.

**Сразу после W1 — первый деплой по `web/DEPLOY.md`**, до W2.

### W2. Новая задача → вопросы ИИ

> Экран «Новая задача» (`#/new`, роль «бизнес»): заголовок «Опишите задачу своими словами»,
> `select` отрасли из `meta.industries`, `textarea` черновика со счётчиком символов, чипы
> «Пример: …» из `meta.draft_examples` (клик подставляет текст и отрасль). Кнопка «Разобрать
> черновик» неактивна при пустом поле → `POST /api/tasks` с `business_id` текущего бизнеса.
> Пока ждём — кнопка заблокирована, лоадер с текстом «ИИ разбирает черновик…» (до ~20 с).
> Ошибка — текст из `message` под полем, введённый текст не теряется.
> После ответа — переход на `#/task/{id}`. Экран задачи при `status: "new"` показывает:
> черновик, текущий рейтинг (`rating.score`, `level_label`), плашку `ai.mode === "stub"`
> («ИИ недоступен, работает локальная заглушка»), `ai.warnings` списком и вопросы
> `task.questions` — каждый карточкой с подписью поля из `meta.fields` и `textarea` для ответа.
> Кнопку отправки ответов сделай, но подключишь в W3.

Готово, если: в моках и с живым бэком слабый пример «Хотим понимать, какие поля скоро потребуют
полива» даёт ≥ 3 вопроса; перезагрузка `#/task/{id}` показывает ту же задачу (`GET /api/tasks/{id}`).

### W3. Ответы → карточка и рейтинг

> На экране задачи: «Собрать карточку» → `POST /api/tasks/{id}/answers` (пустые ответы не
> отправляй — это пропуск). При `status: "card"` — редактор карточки: 10 полей из `meta.fields`
> (`title` — input, остальные — textarea), у поля с `sources[key]` ≠ `"manual"` — значок «цитата»,
> по наведению сама цитата. Справа `RatingPanel`: большое число, уровень, 7 полос `breakdown`
> (`points / max`, `explain`, `hint`), блок «Что поднимет рейтинг» из `next_best` с «+gain».
> Пока пользователь печатает — `POST /api/rating/preview` с debounce 400 мс, панель обновляется
> вживую. Кнопка «Сохранить» → `PUT /api/tasks/{id}/card` только с изменёнными полями.

Готово, если: дописываешь критерий успеха — число в панели растёт без сохранения; после
«Сохранить» у поля пропадает значок цитаты (`manual`).

### W4. Подтверждение, публикация, лента

> Кнопки «Подтвердить карточку» → `POST /confirm` и «Опубликовать» → `POST /publish`
> (активна только при `confirmed: true`; `409` показать текстом). Покажи отдельно «текущий
> рейтинг» (`rating`) и «в каталоге» (`official`) — если они расходятся, подсказка «подтвердите,
> чтобы позиция в каталоге обновилась». `RatingTimeline` из `task.history`: точки со счётом и
> подписью события (черновик / ответы / правка / подтверждение), линия между ними — **главный
> кадр демо**, крупно и над редактором. После публикации — ссылка «Посмотреть в каталоге».

Готово, если: сценарий черновик → ответы → правка → подтверждение даёт ленту из 4 точек с ростом.

### W5. Каталог и отклик (роль «команда»)

> `#/catalog`: `GET /api/catalog` с фильтрами отрасль и уровень (из `meta`). Карточки по порядку
> ответа (бэк уже сортирует), на каждой: позиция `#N`, название, бизнес, отрасль, `score` и
> `LevelBadge`, `summary`, число откликов. `needs_clarification` — бейдж «требует уточнения»,
> `highlight` — выделенная рамка. Сверху «Рекомендуем вам»
> (`GET /api/teams/{id}/recommendations`) с тегами `match` — каталог не фильтрует.
> Клик по задаче → `#/task/{id}` в режиме просмотра (карточка только для чтения + форма отклика):
> идея, план, срок, ссылка → `POST /api/tasks/{id}/proposals`. Валидация до отправки: идея,
> план, срок не пустые, ссылка начинается с `http://` или `https://`. `#/my-proposals` —
> `GET /api/teams/{id}/proposals` со статусами (отправлен / принят / отклонён) и комментарием.

Готово, если: задача с низким рейтингом видна и на неё можно откликнуться; фильтры работают.

### W6. Выбор бизнеса

> `#/my-tasks`: `GET /api/tasks?business_id=` — список со статусом, рейтингом, числом откликов.
> Для опубликованной — «Отклики (N)» → `#/task/{id}/proposals`: `GET /api/tasks/{id}/proposals`,
> отклики карточками рядом для сравнения (команда, идея, план, срок, ссылка). Кнопки «Выбрать» и
> «Отклонить» с необязательным комментарием → `POST /api/proposals/{id}/decision`. Можно выбрать
> несколько или ни одного. Никаких «лучший вариант» и автоподсказок выбора.

Готово, если: принятый отклик у команды в «Мои отклики» виден как «принят».

### W7. ИИ-спека, прогон, сборка

> `#/ai`: `GET /api/ai/spec` — режим и модель, для каждого вызова системный промпт, пример входа
> и JSON-схема выхода (`<pre>` с форматированием), блок «Обработка некорректного ответа».
> Пройди демо из раздела «Порядок вызовов на демо» в `01-api.md` целиком с живым бэком
> (`VITE_USE_MOCKS` выключен). Почини всё, что сломалось. `npm run build` без предупреждений.

Готово, если: весь сценарий ТЗ §11 проходится руками за 3 минуты без перезагрузки страницы.

## Запуск

```bash
# бэк (Python 3.11–3.14) — или одной командой из корня: ./run.sh (соберёт и фронт)
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
cd backend && ../.venv/bin/uvicorn app.main:app --reload --port 8000

# фронт
cd web && npm i
npm run dev                          # с живым бэком
VITE_USE_MOCKS=true npm run dev      # без бэка
npm run build                        # → web/dist, отдаёт FastAPI
```
