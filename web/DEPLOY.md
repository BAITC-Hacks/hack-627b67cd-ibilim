# Деплой: как выложить проект по публичной ссылке

Для тех, кто деплоит впервые. Делай по шагам сверху вниз.

## Зачем это нужно

Проект, который не открывается по публичной ссылке, снимают до финала. Эксперты сами открывают
ссылку и разворачивают проект по README. Поэтому **выкладываем рано** — сразу после шага W1,
когда есть хоть какой-то фронт, — и дальше только обновляем. Не в последний час.

## Как это устроено (одна картинка)

```
твой ноутбук                          Railway (сервер в интернете)
────────────                          ─────────────────────────────
папка репо ── railway up ──────────▶  1. собирает фронт: npm run build → web/dist
                                      2. ставит Python и бэк
                                      3. запускает FastAPI
                                             │
                          https://<имя>.up.railway.app
                             ├── /        → страницы фронта (web/dist)
                             └── /api/... → бэк Арслана
```

Один сервис — одна ссылка. Фронт и бэк живут вместе, поэтому настраивать CORS не нужно.

Словарь:
- **Деплой** — выложить приложение на сервер, чтобы оно открывалось по ссылке у всех.
- **Сборка (build)** — `npm run build` превращает исходники React в обычные HTML/JS-файлы в `web/dist`.
- **Dockerfile** — рецепт для сервера: что установить, что собрать и как запустить.
- **Переменные окружения** — настройки вроде ключа OpenAI. Их задают на сервере, а не в коде.

## Почему Railway

- Код заливается командой `railway up` прямо из папки. Доступ к GitHub-организации
  BAITC-Hacks не нужен (репо приватный, а права на организацию могут не дать).
- Сервер сам собирает Dockerfile, ставить Docker на ноутбук не надо.
- Сразу выдаёт публичный адрес `https://…up.railway.app`.

Код при этом остаётся в нашем репо, и деплоим мы именно его. Это важно: разработка вне выданного
репозитория — дисквалификация.

## Шаг 0. Договориться с Арсланом (2 минуты)

В `AGENTS.md` написано, что `Dockerfile` в конце делает Codex Арслана. Скажи ему, что
**`Dockerfile` и `.dockerignore` в корне делаешь ты, потому что деплой на тебе**. Иначе получите
два разных файла.

## Шаг 1. Dockerfile (делает Codex, после шага W1)

Дай Codex промпт:

> Создай в корне репо `Dockerfile` и `.dockerignore` ровно по `web/DEPLOY.md` (шаг 1).
> Больше ничего не меняй. Закоммить только эти два файла и запушь.

**`Dockerfile`** (корень репо):

```dockerfile
# 1) собираем фронт
FROM node:20-alpine AS web
WORKDIR /web
COPY web/package*.json ./
RUN npm install
COPY web/ ./
RUN npm run build

# 2) бэк + собранный фронт
FROM python:3.12-slim
WORKDIR /app
COPY backend/requirements.txt backend/requirements.txt
RUN pip install --no-cache-dir -r backend/requirements.txt
COPY backend/ backend/
COPY seed/ seed/
COPY --from=web /web/dist web/dist
WORKDIR /app/backend
ENV DB_PATH=/tmp/hub.db
# Railway передаёт порт в переменной PORT
CMD uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

**`.dockerignore`** (корень репо):

```
.git
.venv
**/node_modules
web/dist
**/__pycache__
*.db
*.db-wal
*.db-shm
.env
```

База данных — файл SQLite внутри контейнера. При каждом новом деплое она создаётся заново из
`seed/`. Для демо это нормально, но **задачи, созданные на сайте, после передеплоя пропадут**.

## Шаг 2. Аккаунт и утилита Railway (10 минут, один раз)

1. Зайди на https://railway.com → **Login** → **Login with GitHub**. Проверь, что доступен
   пробный или бесплатный кредит: сервису нужно проработать до конца хакатона.
2. Установи консольную утилиту (в терминале):
   ```bash
   brew install railway
   ```
   Не получилось — `npm i -g @railway/cli`.
3. Войди:
   ```bash
   railway login
   ```
   Откроется браузер — подтверди вход.

## Шаг 3. Первый деплой (10–15 минут)

В терминале, **в корне репо** (там, где лежит `Dockerfile`):

```bash
cd ~/hackathon/hack-627b67cd-ibilim
railway init          # создать проект; имя: challenge-hub
railway up            # залить код и собрать; ждать 3–5 минут
railway domain        # выдать публичную ссылку — СКОПИРУЙ ЕЁ
```

Если `railway up` спросит сервис — выбери тот, что создался. Логи сборки идут прямо в терминал;
последние строки должны быть про `Uvicorn running on http://0.0.0.0:…`.

## Шаг 4. Проверка

Открой в браузере:

| Адрес | Что должно быть |
|---|---|
| `https://<ссылка>/api/health` | `{"ok": true, "db": "ok", "llm": "stub", ...}` |
| `https://<ссылка>/` | главная страница фронта |
| `https://<ссылка>/api/catalog` | список задач из сида |

`"llm": "stub"` значит, что ключа OpenAI нет и работает заглушка. Сценарий при этом проходит
целиком, так и должно быть: эксперты проверяют без наших ключей.

**Ссылку сразу отправь Арслану.** Она нужна в README и для сдачи.

## Шаг 5. Ключ OpenAI (по желанию, когда Арслан скажет)

```bash
railway variables --set "OPENAI_API_KEY=sk-..." --set "OPENAI_MODEL=gpt-5-mini" --set "OPENAI_REASONING_EFFORT=low"
```

Railway сам перезапустит сервис. Проверь `/api/health`: должно стать `"llm": "llm"`.
Ключ **никогда не коммить** в репо и не вставляй в код.

## Шаг 6. Обновление (каждый час, после push)

```bash
git pull --rebase     # забрать изменения Арслана
git push              # отправить свои
railway up            # обновить сайт тем, что лежит в папке
```

Затем проверь `/api/health` и главную. Сайт обновляется за 3–5 минут.
**После 17:40 больше не деплой** — код заморожен, дальше только прогон демо.

## Если что-то сломалось

| Что видишь | Что делать |
|---|---|
| сборка падает на `npm run build` | локально `cd web && npm run build`, почини ошибку, `railway up` ещё раз |
| сборка падает на `COPY web/package*.json` | шаг W1 ещё не сделан — в `web/` нет `package.json` |
| сборка падает на `pip install` | пришли Арслану кусок лога — это его зона |
| `/api/health` работает, а `/` отдаёт 404 | фронт не собрался: в логе сборки ищи шаг `npm run build` |
| страница открывается, но данных нет | в `web/src/api.js` включены моки — `VITE_USE_MOCKS` при сборке быть не должно |
| `Application failed to respond` | в логах (`railway logs`) ищи ошибку Python и пришли Арслану |
| кончился кредит Railway | план Б ниже |

Логи сервера: `railway logs`. Открыть панель проекта в браузере: `railway open`.

## План Б — Render

Подходит, если Railway не взлетел. Render берёт код из GitHub, поэтому администратор организации
BAITC-Hacks должен дать доступ к репо (спроси организаторов).

1. https://render.com → вход через GitHub → **New → Web Service** → выбрать репо.
2. Runtime: **Docker** (Dockerfile тот же). Instance: Free.
3. **Create** → через 5–10 минут появится ссылка `https://…onrender.com`.
4. Каждый push в `main` деплоится сам.

Бесплатный Render засыпает после 15 минут без запросов, первое открытие — до минуты.
**Перед демо открой ссылку заранее.**
