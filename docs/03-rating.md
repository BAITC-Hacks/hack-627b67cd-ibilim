# Рейтинг и каталог

Рейтинг считает `backend/app/rating.py` по **подтверждённой человеком** карточке. Формула
детерминированная: сумма баллов за 7 показателей, максимум 100. ИИ не выставляет баллы.
Предпросмотр использует ту же формулу, но место в каталоге меняется только после подтверждения.

Пустые строки и заглушки `-`, `—`, `?`, `нет`, `не знаю`, `н/д`, `неизвестно`, `пока нет`,
`нет данных` баллов за заполнение не дают. Содержательным считается текст хотя бы с тремя
буквами. Число — любая цифра; проверка не утверждает, что заявленный показатель достижим.

| Показатель | Проверки и баллы | Макс. |
|---|---|---:|
| Контекст и потребность | контекст указан +6; потребность указана +6; в контексте есть число +4; в потребности есть число +4 | 20 |
| Данные и материалы | описание +8; назван источник (например, датчики, CRM, выгрузка, документы) +6; указан формат (CSV, Excel, JSON, API, PDF, SQL) +3; есть число объёма или периода +3 | 20 |
| Ожидаемый результат | описание +8; не менее 6 слов +4; есть число +3 | 15 |
| Критерии успеха | описание +5; есть числовая цель +7; названа метрика (точность, время, ошибки и т. п.) +3 | 15 |
| Ограничения | описание +5; есть числовая граница +3; названа категория (срок, бюджет, доступ, безопасность и т. п.) +2 | 10 |
| Пользователи | названы +6; описание роли не короче 4 слов +4 | 10 |
| Связь с бизнесом | контакт похож на email, телефон, @ник или ссылку +6; описан формат взаимодействия +4 | 10 |

Дополнительная проверка начисляется только при содержательном основном поле. Каждое сработавшее
правило перечислено в `breakdown.explain` со своими баллами, несработавшее даёт подсказку в
`breakdown.hint`. `missing` содержит показатели с нулём баллов. `next_best` содержит все
недобранные показатели, `gain = max − points`, по убыванию потенциального прироста.
`next_level` показывает следующий уровень и `points_needed` — разницу между его нижней границей
и текущим баллом; для `priority` он равен `null`.

Итоговый `score = max(0, сумма breakdown.points − сумма penalties.points)`. Штрафы тоже
детерминированны, каждый содержит причину в `explain`:

| Ключ | Когда снимаются баллы |
|---|---|
| `duplicate` | Тексты двух оцениваемых полей совпадают или имеют не менее 80% общих уникальных слов относительно более длинного текста. Первое поле сохраняет баллы, повторное — нет. |
| `keyword_soup` | Поле короче 5 слов, не менее 80% слов — ключевые слова рейтинга (например, `csv api excel json`). Бонусы за источник и формат данных либо метрику успеха снимаются. |
| `filler` | Отписки «см. выше», «уточним позже», «аналогично», `tbd`, `todo` и подобные считаются пустым полем. |
| `gibberish` | Текст без гласных или с серией из четырёх одинаковых букв считается пустым полем; известные сокращения вроде `CSV` и `SQL` не затрагиваются. |

Короткая осмысленная формулировка, например «точность прогноза не ниже 80%», сохраняет баллы.

Уровни: `draft` 0–39, `working` 40–69, `ready` 70–89, `priority` 90–100.
Низкий рейтинг не запрещает публикацию и отклик. Каталог показывает все опубликованные задачи
по официальному баллу подтверждённой карточки, при равенстве — новые выше. `draft` помечается
как требующий уточнения, `priority` выделяется.
`place(conn, score, task_id)` возвращает место среди опубликованных задач (без `task_id`): перед
задачей считаются только баллы строго выше; прогноз для черновика использует тот же расчёт.
