# Кейс: AI Sana Challenge Hub — от бизнес-задачи к решению

Трек «Образование», HackAlem AI, 23.09.2026. Полное ТЗ:
https://docs.google.com/document/d/1lFWekP2SirFarATKkWa5neHNL5DlhjZKkUacvGyZk8k

## Суть

Бизнес описывает потребность своими словами — система помогает дописать недостающее, считает
рейтинг готовности и публикует карточку в общем каталоге. Любая студенческая команда откликается,
бизнес сам сравнивает отклики и выбирает одну, несколько или ни одной. **Главная геймификация —
для бизнеса**: чем полнее и полезнее описана задача, тем выше рейтинг и позиция в каталоге.

## Сценарий (ТЗ §2)

| # | Шаг | Что происходит |
|---|---|---|
| 1 | Черновик | бизнес вводит краткое описание |
| 2 | Уточнение | система находит недостающее и задаёт **не меньше трёх** уместных вопросов |
| 3 | Карточка | из ответов — редактируемая карточка, бизнес подтверждает |
| 4 | Рейтинг | баллы за полноту и что добавить, чтобы рейтинг вырос |
| 5 | Каталог | подтверждённая задача публикуется на позиции по рейтингу |
| 6 | Выбор студентов | команда смотрит каталог или рекомендации и подаёт предложение |
| 7 | Выбор бизнеса | бизнес сравнивает и сам выбирает — автоназначение запрещено |
| 8 | Результат | после подтверждённого этапа команда получает баллы за прогресс (у нас MVP-2) |

## Карточка (ТЗ §3)

Название, контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии
успеха, контакт, формат взаимодействия. Плюс отрасль — для фильтра каталога.

## Рейтинг (ТЗ §4)

| Показатель | Вес |
|---|---|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Уровни: 0–39 черновик (виден, помечен «требует уточнения») · 40–69 рабочая (можно рекомендовать)
· 70–89 готовая (повышенная позиция) · 90–100 приоритетная (выделяется). Баллы — только за
заполненные **и подтверждённые** поля; пересчёт после каждого подтверждённого дополнения. Низкий
рейтинг не скрывает задачу и не запрещает отклик. Точные правила — `docs/03-rating.md`.

## ИИ (ТЗ §5)

Минимум одна содержательная ИИ-функция. У нас две: разбор черновика с вопросами и сборка карточки
из ответов. ИИ не добавляет фактов, текст правит и подтверждает человек, ИИ может рекомендовать
задачи командам, но не выбирает исполнителей. Без API — локальная заглушка, но показать промпт,
формат входа и выхода и обработку некорректного ответа: для этого `GET /api/ai/spec`.

## Наши решения

1. **Рейтинг считает код**, а не модель: прозрачно, мгновенно пересчитывается, у каждого балла
   объяснение и подсказка «что добавить» — это 25 баллов «геймификации бизнеса».
2. **Проверка цитат**: для каждого поля модель возвращает дословную цитату из черновика или
   ответов, код ищет её в тексте; не нашёл — значение отброшено и показано в `ai.warnings`.
3. **Лента рейтинга** (`history`): 12 → 38 → 81 — рост виден на одном экране.
4. Вход без регистрации — переключатель «я — бизнес X / я — команда Y» (ТЗ §7 это разрешает).

## Данные (ТЗ §6)

Синтетические, минимум по 5: черновики (разной полноты), карточки (все поля рейтинга и текущий
балл), профили команд (название, интересы, навыки, технологии), отклики (команда, идея, план,
срок, ссылка). Лежат в `seed/*.json`, грузятся `python -m app.db`.

## Демо (ТЗ §11, до 5 минут)

Слабое описание → дополняем → рейтинг растёт → публикуем → задача в каталоге на своём месте →
команда откликается → бизнес вручную принимает или отклоняет. Всё в MVP, не на слайдах.

## Сдача (ТЗ §10)

Репозиторий; MVP, который запускается по инструкции; README с архитектурой, формулой рейтинга,
правилами каталога и тестовыми сценариями; демо до 5 минут.
