# Пайплайны

## 1. Ingest программы → граф целей

Источник — типовые учебные программы (приказ, приложения) и типовые учебные планы.
Это НПА, открытые данные. Формат внутри: долгосрочный план, где цели разложены по четвертям
и разделам.

```
скачать приложение по предмету
 → выдрать таблицы долгосрочного плана
 → строки: раздел / подраздел / цель / четверть
 → нормализовать код в класс.раздел.подраздел.номер
 → сохранить text_ru и text_kk
 → LLM предлагает prerequisites внутри предмета → человек подтверждает
 → objective в БД
```

`seed/objectives.7.algebra.json` — **черновой** набор для демо-раздела. Его формулировки надо
сверить с приказом до питча: показывать на сцене «государственную программу» с выдуманными
формулировками нельзя. Поле `"source": "DRAFT"` стоит в каждом объекте именно для этого.

## 2. Планировщик КТП

```
вход: klass, calendar(quarter), schedule_slot[], objectives(quarter) с hours
1. развернуть учебные даты четверти по расписанию, минус каникулы и праздники
2. отсортировать цели по order_index
3. распределить: часы раздела → количество уроков, цели ложатся подряд
4. создать lesson(date, objective_codes, topic)
5. вернуть «дата → тема → цели»
```

Пересчёт (MVP-2): урок помечен `skipped` → шаги 3–4 заново от текущей даты,
в ответ добавляется `warning: "отставание 3 часа"`.

## 3. Персональная домашка

```
для каждого ученика класса:
  today = цели урока                       → 60% заданий
  gaps  = цели с mastery < 0.5,
          отсортированные по тому,
          блокируют ли они today
          (prerequisites пересекаются)     → 40% заданий
  уровень задания = f(mastery по цели):
     mastery >= 0.8 → level 3
     0.5–0.8        → level 2
     < 0.5          → level 1
  развернуть шаблоны: seed = hash(student_id, template_id) → числа из params
  посчитать эталон по answer_rule подстановкой
```

Важно: эталон считается **кодом** (sympy), а не моделью. Модель дала формулу — код подставил
числа и получил ответ. Поэтому проверка потом сходится.

## 4. Проверка

```
ответ (web / phone / paper)
 → если фото: read_photo → answer_raw по item_id
 → числовой ответ? sympy.simplify(ученик - эталон) == 0
 → grade_answer: дескрипторы, шаги, used_objective_codes, confidence, feedback
 → расхождение sympy и модели ИЛИ confidence < 0.7 → needs_teacher
 → item_result
 → mastery: value = 0.6*old + 0.4*(score/max)
```

## 5. Детектор внешней помощи

Не стилометрия. Считаем взвешенную сумму сигналов, каждый из которых объясним словами.

| сигнал | вес | как считается |
|---|---|---|
| метод вне пройденного | 0.45 | `used_objective_codes` содержит код, которого нет в `taught_codes` на дату урока |
| разрыв с историей | 0.20 | `mastery < 0.35` по цели, при этом `score == max` и нет ошибок |
| пропуск шагов | 0.10 | число шагов в решении меньше эталонного более чем вдвое |
| вставка из буфера | 0.15 | `telemetry.pastes > 0` (web/phone) |
| скорость | 0.10 | `telemetry.seconds` меньше 15% медианы класса по этому заданию |

```
score = Σ(вес × сработал)
level: < 0.3 low | 0.3–0.6 medium | >= 0.6 high
```

Правила, без которых фича становится вредной:

1. **Порог от личной истории, а не от класса.** У стабильно сильного ученика (средняя mastery
   по предмету ≥ 0.8) «метод из будущего» даёт не флаг, а пометку `advanced` —
   «ему скучно, дайте уровень 3».
2. **Основания всегда текстом и в терминах кодов целей**: «метод относится к цели 8.1.2.3,
   2 четверть 8 класса». Не «похоже на ИИ».
3. **Никаких автоматических санкций.** Высокий индекс = строка в очереди учителя.
4. На бумажном канале телеметрии нет вообще — доступны только первые три сигнала,
   и это честно показывается в карточке (`signals_available`).

## 6. Бланк с QR (MVP-2)

В QR: `student_id|lesson_id|item_ids`. Печать — HTML + `window.print()`, разрыв страницы
между учениками. При загрузке фото: детект QR → ответы режутся по боксам → дальше обычная
проверка. Без QR результаты помечаются `needs_teacher`.

Зачем вообще: рукописное распознавание на кириллице даёт 60–85% точности, поэтому произвольная
тетрадь — это каша, а размеченный бланк — рабочий вход. Плюс тот же QR служит логином ученика.
