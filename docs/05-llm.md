# LLM: вызовы, схемы, промпты

Все вызовы идут через `backend/app/llm.py`. Больше нигде OpenAI не импортируется.
Везде Structured Outputs (`response_format = {"type":"json_schema", "json_schema": {..., "strict": true}}`).
Свободного текста между слоями нет: не сошлась схема — ретрай (до 2 раз), потом честная ошибка.

`PROMPT_VERSION` — константа в `llm.py`, входит в ключ кеша. Поменял промпт — бампни версию.

---

## 1. `gen_lesson_pack` — пакет урока (КСП)

**Вход:** цели урока (коды + тексты + prerequisites), класс, язык, `textbook_ref`,
агрегированная `mastery` класса по этим целям и по их prerequisites.

**System:**
> Ты методист казахстанской школы. Ты составляешь краткосрочный план урока (КСП) строго по
> целям обучения государственной типовой учебной программы. Ты не выдумываешь цели и не
> ссылаешься на материал, которого нет в переданных целях и их пререквизитах. Пиши на языке
> обучения класса. Формулировки результатов — глаголами действия («применяет», «различает»).

**User:** коды и тексты целей, сколько минут урок (45), состояние класса
(«7.2.1.1 освоена у 82%, 7.2.1.2 у 47%»), ссылка на параграф учебника, язык.

**Схема ответа:** `ksp{goals[], outcomes[], stages[{minutes,title,activity}], differentiation,
assessment}`, `explanation`, `common_mistakes[{mistake,why,fix}]`,
`classwork[{item_id,level,statement,answer}]`,
`homework_template[{template_id,objective_code,level,statement_tpl,params,answer_rule,descriptors[]}]`.

Ключевое в шаблоне домашки: `statement_tpl` содержит плейсхолдеры `{a}`, `{b}`, а `params` —
допустимые значения. Разворачивает их код, а не модель: у каждого ученика свой `seed`,
у всех одна и та же проверяемая формула `answer_rule`.

## 2. `gen_gap_items` — задания на добор пробела

**Вход:** цель, у которой у ученика низкая `mastery`, уровень 1–2, язык.
**Выход:** 2–3 объекта того же формата, что `homework_template`.

**System:** дополнительно:
> Задание должно тренировать ровно указанную цель и не требовать методов из целей, которых нет
> в списке пройденных. Если для решения нужен метод из другой цели — перепиши задание.

Это правило — та же логика, что у детектора, но на входе: мы сами не выдаём ученику задачу,
которую нельзя решить пройденным аппаратом.

## 3. `grade_answer` — проверка ответа

**Вход:** условие, эталон `answer`, `descriptors[]`, ответ ученика (текст или распознанный с фото),
список **пройденных кодов целей на дату** (`taught_codes`), `mastery` ученика по этой цели.

**System:**
> Ты проверяешь работу ученика по критериям (дескрипторам), а не «на глаз». Для каждого
> дескриптора реши, выполнен он или нет, и выставь баллы. Отдельно разбери решение на шаги и
> для каждого шага укажи, какой математический метод применён. Не оценивай стиль речи и не
> делай выводов о списывании — только факты о решении.

**Схема:**
```json
{
  "correct": true,
  "score": 2,
  "descriptors_hit": ["..."],
  "steps": [{ "step": "раскрыл по формуле квадрата суммы", "method": "формула сокращённого умножения" }],
  "used_methods": ["формула квадрата суммы"],
  "used_objective_codes": ["7.2.1.4"],
  "confidence": 0.93,
  "feedback": "одно-два предложения ученику, по делу, без похвалы ради похвалы",
  "misconception": "если ошибся — какое именно заблуждение видно"
}
```

`used_objective_codes` — то, чем кормится детектор. Модель сопоставляет метод с кодами из
переданного справочника целей (вместе с целями соседних классов, чтобы она могла назвать
«метод из будущего»). Если метод не опознан — пустой массив, детектор просто не получает сигнал.

**Численные ответы проверяет sympy, а не модель.** Порядок: сначала `sympy.simplify(ученик - эталон) == 0`,
и только потом LLM для дескрипторов и разбора. Если sympy сказал «верно», а модель «неверно» —
верим sympy и ставим `needs_teacher = true`.

## 4. `read_photo` — распознавание работы с фото

Мультимодальный вызов. Вход: изображение + список ожидаемых заданий (их условия).

**System:**
> Извлеки ответы ученика по каждому заданию ровно в том виде, как они записаны. Не решай
> задачи и не исправляй ошибки ученика. Если фрагмент не читается — верни `null` и низкую
> уверенность для этого задания.

**Схема:** `items[{item_id, answer_raw, work_raw, confidence}]`.

Пункт, который легко забыть: модель обожает «помогать» и дописывать правильное решение.
Требование «не решай» повторяется в user-сообщении ещё раз. Всё, что пришло с `confidence < 0.7`,
идёт в очередь учителю.

## 5. `probe_questions` — микро-опрос (MVP-2)

Вход: решение ученика. Выход: 2 коротких вопроса по его же решению + эталонные признаки
верного ответа. Ответы ученика проверяются тем же `grade_answer` в упрощённом режиме.

---

## Кеш и стоимость

- Ключ: `sha256(objective_code + level + language + PROMPT_VERSION)`.
- Кешируются `gen_lesson_pack` и `gen_gap_items`. Проверка ответов не кешируется.
- Один вариант обслуживает много классов: меняется только `seed` (числа), а условие и
  `answer_rule` переиспользуются. Цифру «тенге на ученика в месяц» считаем перед питчем —
  её спрашивают.

## Фолбэк, когда всё горит

Если API недоступен или кончился лимит: `DEMO_MODE=1` в `.env` заставляет `llm.py` отдавать
заранее сохранённые ответы из `seed/fixtures/*.json` для целей демо-раздела. Демо должно
пережить падение сети в зале — это не читерство, это страховка, и она названа в README.
