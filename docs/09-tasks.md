# Задачи и готовые промпты для Codex

Порядок важен: каждая задача опирается на предыдущую. Промпты можно давать Codex дословно —
он подхватит `AGENTS.md` сам, поэтому контекст в промпте повторять не нужно.

## A — LLM и бэкенд

**A1. Планировщик КТП** (30 мин)
> Реализуй `backend/app/planner.py` и роут `POST /api/classes/{id}/plan/build` по
> `docs/06-pipelines.md` §2 и `docs/04-api.md`. Берёт `calendar`, `schedule_slot`, цели четверти
> из `objective`, раскладывает по датам с учётом часов и каникул, пишет строки в `lesson`.
> Затем `GET /api/classes/1/plan` должен возвращать заполненный план. Добавь короткий тест,
> что число уроков равно числу учебных дат.

**A2. Пакет урока** (45 мин)
> Реализуй `backend/app/generate.py::lesson_pack` и `POST /api/lessons/{id}/pack` по
> `docs/05-llm.md` §1. Структурированный вывод строго по схеме, результат в `lesson_pack`,
> кеш через `gen_cache` с ключом из `llm.cache_key`. При `?force=true` — перегенерация.

**A3. Персональная домашка** (40 мин)
> Реализуй `generate.py::homework` и `POST /api/lessons/{id}/homework` по `docs/06-pipelines.md` §3:
> 60% цели урока, 40% просевшие цели из `mastery`, уровень из mastery, `seed = hash(student_id, template_id)`,
> подстановка чисел в `statement_tpl`, эталон считается sympy по `answer_rule`.
> Никакого обращения к LLM на этом шаге — только разворачивание шаблонов.

**A4. Проверка** (50 мин)
> Реализуй `backend/app/grade.py` и `POST /api/submissions` по `docs/06-pipelines.md` §4 и
> `docs/05-llm.md` §3. Порядок: sympy сравнивает ответ с эталоном → LLM разбирает шаги и
> дескрипторы → расхождение или `confidence < CONFIDENCE_THRESHOLD` даёт `needs_teacher`.
> Обнови `mastery` по формуле сглаживания. Верни ответ ровно в формате `docs/04-api.md`.

**A5. Детектор** (30 мин)
> Реализуй `backend/app/detector.py` по `docs/06-pipelines.md` §5: взвешенная сумма сигналов,
> основания текстом со ссылкой на код цели и класс/четверть, где эта цель проходится.
> Учти правило про сильного ученика (`advanced` вместо флага) и `signals_available` для бумаги.
> Подключи к `item_result` и к `GET /api/teacher/review-queue`.

**A6. Фото** (30 мин)
> Реализуй `POST /api/submissions/photo`: чтение изображения, `llm.call_vision` по
> `docs/05-llm.md` §4 (модель НЕ решает задачи), сопоставление с `assignment_item`,
> дальше общий путь проверки. Всё с `confidence < 0.7` — в очередь учителю.

**A7. Фикстуры для DEMO_MODE** (15 мин, обязательно до демо)
> Сохрани реальные ответы всех вызовов LLM демо-сценария в `seed/fixtures/<name>.json`,
> проверь, что при `DEMO_MODE=1` весь сценарий из `docs/07-demo.md` проходит без сети.

## B — веб и деплой

**B1. Каркас и деплой** (30 мин)
> Создай `web/` на Vite + React, страницы «Учитель» и «Ученик», прокси `/api` на :8000,
> сборка в `web/dist` (её раздаёт бэкенд). Задеплой пустую оболочку на публичный URL прямо сейчас:
> по регламенту непубличный проект отклоняют до финала.

**B2. Экран учителя: план** (40 мин)
> `GET /api/classes/1/plan` → список уроков по датам, карточка урока, кнопка «Собрать пакет»
> (`POST /api/lessons/{id}/pack`, ответ до 30 секунд — нужен лоадер с текстом, что идёт генерация).

**B3. Экран урока** (40 мин)
> Показать КСП по этапам с минутами, объяснение, типовые ошибки, задания трёх уровней,
> кнопку «Выдать домашку классу» (`POST /api/lessons/{id}/homework`) и список учеников
> с их фокусными целями.

**B4. Экран ученика** (45 мин)
> `GET /api/students/{id}/homework?lesson_id=` → задания, поле ответа на каждое,
> кнопка «Сдать» (`POST /api/submissions`). **Обязательно** собирать телеметрию на каждое поле:
> `seconds` с момента фокуса, `pastes` (событие paste), `edits` (число изменений) — это кормит детектор.
> После сдачи — разбор: баллы, дескрипторы, фидбек.

**B5. Фото и мобильный вид** (30 мин)
> Загрузка снимка через `<input type="file" capture="environment">` →
> `POST /api/submissions/photo`, сжатие на клиенте до ~1600px. Проверить на телефоне:
> страница должна работать при ширине 390px.

**B6. Карта класса** (30 мин)
> `GET /api/classes/1/mastery` → таблица целей с процентом освоения, красным подсвечены
> проваленные, рядом рекомендация. Плюс `GET /api/teacher/review-queue` — карточка с индексом
> внешней помощи и списком оснований.

**B7. PWA и финал** (20 мин)
> manifest, иконка, `display: standalone`, проверка установки с телефона. Прогон демо-сценария
> из `docs/07-demo.md` целиком, запись экрана как страховка.

## Общее правило на последний час

В 4:40 код замораживается: README, прогон сценария, запись экрана. Демо, которое не показали,
стоит ноль — независимо от того, что осталось в ветке.
